## Goal: G14 — MCP agent bridge

> **Status: done (v0.5).** Notes from the PR:
>
> - The bridge is two halves that meet on loopback: `mcp/server.mjs` is a zero-dependency Node ≥20
>   stdio MCP server writing `~/.prompty`; the extension background polls `GET /pending` on a
>   one-minute `alarms` clock, imports, acks, and posts its library back as a snapshot.
> - Off by default. No request exists until Settings → Agent bridge is enabled. The extension
>   refuses any URL that is not `127.0.0.1`/`localhost`.
> - The 48-hex token is generated by the MCP server (`~/.prompty/bridge.json`, 0600) and stored by
>   the extension under its own key, outside `settings`, so JSON exports never contain it.
> - Import preserves agent ids, dedupes by normalized text, creates missing categories, applies
>   tombstones, and acks every processed id. Marking a sync complete never depends on the snapshot
>   POST succeeding.
> - Eight tools: `save_prompt`, `list_prompts`, `search_prompts`, `get_prompt`, `update_prompt`,
>   `delete_prompt`, `list_categories`, `bridge_status`.

### Objective

Let a coding agent (Claude Code, Cursor, Claude Desktop, any MCP client) add prompts to the
user's Prompty library, so *"add a camera movement for a slow dolly zoom"* becomes a saved,
categorized prompt within a minute — without giving the extension a cloud account or a remote
server.

### Context

An MCP server cannot write `browser.storage.local`; an extension cannot speak stdio. The smallest
honest bridge is a local queue plus a token-authenticated loopback API. Prompts still work while
the browser is closed, and the extension keeps full control of validation and storage.

### Deliverables

- [x] `mcp/` — zero-dependency Node ≥20 stdio MCP server (`node mcp/server.mjs`): store at
      `~/.prompty`, atomic writes, corrupt file recovered to empty, tombstones capped.
- [x] Bridge API v1 (`GET /health`, `GET /pending`, `POST /ack`, `POST /snapshot`) on
      `127.0.0.1:47821` (env `PROMPTY_BRIDGE_PORT`), all token-authed.
- [x] Extension: `src/lib/bridge.js` (URL guard, payload validation, merge), `bridge-client.js`
      (pending → merge → ack → snapshot), background alarm + single-flight sync, Settings →
      Agent bridge (enable, URL, token, Test, Sync now, last-sync status).
- [x] `alarms` permission; token in `mcpBridgeToken`; i18n en + fr.
- [x] Docs: `mcp/README.md`, root README, landing-page section, CHANGELOG, SPEC Δ14, SECURITY.

### Definition of Done

- [x] End-to-end with a real MCP handshake (`initialize` → `tools/list` → `tools/call save_prompt`)
      and a real HTTP sync into a shim storage area: save → import → ack → search → delete → sync
      removes.
- [x] 401 without/with wrong token, 405 wrong method, 400 bad JSON, 413 over 1 MB, no CORS header,
      `Cache-Control: no-store`, token never echoed.
- [x] Gates: type-check, lint, tests, package; `web-ext lint` / `addons-linter` clean.

### Anti-Drift Rules

- The bridge never leaves loopback and never runs unless the user enables it.
- Prompts cross the boundary only through the storage normalizers; a payload cannot write an
  arbitrary key.
- The token never enters `settings`, an export, a page, or a log line echoed by the API.
