## Goal: G8 — Accessibility and translation baseline

> **Status: G8a (accessibility) done; G8b (popup translation, English + French) done; G8c (in-page UI translation) done.** G8 is split in two because moving
> every UI string to `_locales/` touches every popup file, and that is better as its own PR.
>
> G8a findings from axe-core 4.10 (`scripts/a11y-audit.mjs`), across 9 views × light/dark, all
> fixed (0 violations):
>
> - **Critical:** the Composer's shot `tablist` contained a non-tab (+ Shot). Tabs now sit in their
>   own list; the cut labels are `aria-hidden`; each tab is named, e.g. "Shot 2, 3 seconds, after
>   a match cut".
> - **Serious:** scrollable regions (the Composer preview, the main view) had no keyboard access;
>   both are now focusable and named.
> - The three sidebar `<nav>` landmarks had no labels. They are now named "Views", "Categories" and
>   "Settings".
> - `role="dialog"` was set on `<form>`, which ARIA doesn't allow; it moved to the overlay, which
>   is labelled by the dialog title.
>
> Beyond axe:
>
> - The whole view was an `aria-live` region, so a screen reader re-read the grid on every render
>   (toasts already announce changes). The Composer preview announced every keystroke. Both are
>   removed.
> - Modals and the palette now trap Tab and Shift+Tab (`aria-modal`).
> - `prefers-reduced-motion` stops transitions and animations.
>
> Not covered yet: the in-page UI in the content script's shadow DOM (pill, widget, `!` palette),
> which needs its own audit harness on a test page.
>
> G8b notes:
>
> - **One source of truth:** `src/locales/<lang>.js` (444 keys). `scripts/build.mjs` writes
>   `_locales/<lang>/messages.json`, doubling a literal `$` and rejecting bad keys. The manifest
>   uses `default_locale: "en"` and `__MSG_*__` for its name, description and command names.
> - **`t(key, …subs)`** asks `browser.i18n` first, then the bundled English catalog (tests). Messages
>   use `$1…$9`.
> - **`tn(key, n)`** picks `_one`/`_other` with `Intl.PluralRules` for the UI language, so French
>   counts 0 and 1 as singular.
> - Static HTML uses `data-i18n` and `data-i18n-<attr>`. `<html lang>` follows the UI language.
> - Labels that come from lib ids (slots, cuts, formats, templates) are looked up as `slot_<id>` and
>   the like. Composer checks return `{ key, args }` next to their English `text`. Month names
>   come from `Intl.DateTimeFormat`.
> - **Not translated, on purpose:** prompt text, seed prompts and category names (user data); the
>   text written for models (G9b/G9c output); and developer-facing recipe/JSON validation messages.
> - **`tests/i18n.test.mjs`** checks en/fr key parity, matching `$N` placeholders, complete plural
>   pairs, no `$x$` sequences, that every `t()`/`tn()`/`data-i18n` key exists, and that no
>   capitalized English UI literal is left in `src/popup` (short allow-list).
> - **G8c, done:**
>   - **In-page strings:** the pill, widget, `!` palette, save dialog, toasts and insert errors use
>     `tr(key, englishFallback, …subs)` (`chrome.i18n.getMessage`) with the same catalogs. A test
>     checks that every fallback equals the English catalog text, and that no English literal is
>     written straight into in-page UI.
>   - **Grammar messages:** the variable grammar's validation messages stay English inside the
>     shared block (verbatim parity), and are mapped at display time by `localizeVarProblem` in the
>     popup and `trVarProblem` in the page.
> - **Originally planned for G8c:**
>   - the content script's pill, widget and `!` palette, via `chrome.i18n.getMessage` with the
>     same catalogs
>   - the variable-validation messages inside the shared grammar block

### Objective

Everything in the popup and the in-page UI works by keyboard and screen reader and passes
WCAG 2.1 AA contrast. All UI strings move into `_locales/` so the extension can be translated.
French is the first translation.

### Deliverables

- [x] Accessibility audit with fixes (G8a):
  - focus order, visible focus rings, roles and labels on icon buttons
  - `aria-live` regions for toasts
  - modals trap focus
  - `prefers-reduced-motion` respected
- [x] `_locales/en/messages.json` plus `fr`; a `t(key, …subs)` helper (`browser.i18n`, with a
      fallback in tests); manifest name and description translated.
- [x] A test that fails when a UI string is not in the catalog (scan for literal strings passed to
      `h()` text children in `src/popup`).

### Definition of Done

- [ ] axe-core run in headless Chromium with 0 serious issues; keyboard-only e2e of each view; a
      French screenshot; gates green.

### Anti-Drift Rules

- Prompt contents and seed prompts are user data, not UI strings: they are not translated.
